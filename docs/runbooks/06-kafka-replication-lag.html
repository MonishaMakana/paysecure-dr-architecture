Runbook 06: Kafka Replication Lag

Scope

This runbook covers sustained replication lag between Mumbai and Hyderabad Kafka clusters.

Objective

  • Reduce replication lag to acceptable levels
  • Prevent stale payment event data from blocking settlement

Preconditions

  • MirrorMaker 2 metrics are available in CloudWatch.
  • Network path between regions is healthy.
  • Topic partitions and replication configuration are correct.

Immediate Actions

  1. Review MirrorMaker 2 lag metrics and network latency.
  2. Identify whether the lag is caused by throughput, CPU, or network issues.
  3. Throttle producers or temporarily reroute to the local cluster if required.

RTO Steps

  1. Increase MirrorMaker 2 consumer/producer throughput settings.
  2. Scale MSK brokers or increase partition parallelism.
  3. Clear backlog by replaying unreplicated records.

Validation

  • Confirm lag drops below threshold.
  • Validate payment and settlement event continuity.
  • Monitor downstream consumers for catch-up.

Post-Recovery Activities

  • Review partition sizing and MirrorMaker 2 configuration.
  • Update alert thresholds for lag.
  • Document performance tuning steps.
