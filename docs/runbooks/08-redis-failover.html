Runbook 08: ElastiCache Redis Failover

Scope

This runbook covers failover for ElastiCache Redis when the primary cache cluster fails.

Objective

  • Promote the secondary Redis instance in Hyderabad
  • Restore cache-dependent services quickly
  • Keep RTO under 5 minutes

Preconditions

  • Redis global datastore replication is configured.
  • Application uses DNS alias for Redis endpoint.
  • Health checks and failover alarms are enabled.

Immediate Actions

  1. Identify the Redis failure through CloudWatch metrics and alarms.
  2. Confirm primary cluster health status.
  3. If primary is down, trigger Global Datastore failover.

RTO Steps

  1. Promote Hyderabad replica to primary using ElastiCache failover.
  2. Update Redis alias if auto-swap does not occur.
  3. Flush stale connections and allow the application to reconnect.

Validation

  • Confirm Redis client connectivity.
  • Validate cache key access and TTL behavior.
  • Confirm application performance recovers.

Post-Recovery Activities

  • Document failover cause.
  • Review cache population and cold-start timing.
  • Adjust failover thresholds and automation.
