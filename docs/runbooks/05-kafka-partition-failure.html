Runbook 05: Kafka Partition Failure

Scope

This runbook covers partition outages and broker failures within the Apache Kafka environment.

Objective

  • Restore Kafka topic availability rapidly
  • Prevent message loss and maintain consumer continuity

Preconditions

  • MSK clusters are deployed in Mumbai and Hyderabad.
  • MirrorMaker 2 is configured for cross-region replication.
  • Consumer groups have retry and fallback logic.

Immediate Actions

  1. Identify the impacted topic or partition via Kafka broker metrics.
  2. Review broker state in Amazon MSK.
  3. If a broker is unhealthy, trigger automated broker replacement.

RTO Steps

  1. Validate partitions are rebalanced.
  2. Confirm MirrorMaker 2 continues replicating messages.
  3. Restart affected consumers or switch them to the healthy region cluster.

Validation

  • Check consumer lag for impacted topics.
  • Confirm settlement and fraud event streams resume.
  • Verify no high-priority messages remain unprocessed.

Post-Recovery Activities

  • Document partition failure cause.
  • Adjust MSK broker sizing or partition counts as needed.
  • Review Kafka monitoring thresholds.
