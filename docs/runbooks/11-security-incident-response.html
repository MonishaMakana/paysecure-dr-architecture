Runbook 11: Security Incident Response

Scope

This runbook covers security incidents that impact disaster recovery or business continuity, including potential breaches in payment infrastructure.

Objective

  • Contain and remediate security incidents rapidly
  • Preserve forensic evidence and maintain compliance

Preconditions

  • Incident response plan and security operations processes exist.
  • CloudTrail, GuardDuty, and VPC Flow Logs are enabled.
  • Communication channels for incident response teams are established.

Immediate Actions

  1. Identify the incident type (intrusion, data exfiltration, service compromise).
  2. Isolate the affected region or service.
  3. Capture logs and snapshot affected infrastructure.

RTO Steps

  1. Failover to the backup region if the primary region is compromised.
  2. Rotate credentials, secrets, and API keys.
  3. Rebuild affected infrastructure from secure IaC templates.

Validation

  • Confirm the incident is contained.
  • Validate restored services in the recovery region.
  • Ensure forensic evidence is preserved.

Post-Recovery Activities

  • Conduct a post-incident review.
  • Update security controls and runbooks.
  • Notify regulators and stakeholders as required.
