Runbook 07: Peak Load Failover

Scope

This runbook covers failover and scaling under high transaction volume spikes.

Objective

  • Maintain service responsiveness during peak demand
  • Ensure uptime and recoverability when load exceeds thresholds

Preconditions

  • Autoscaling policies are configured for ECS/EKS, Aurora, DynamoDB, and MSK.
  • Burst capacity is modeled for 3.2 million daily transactions.
  • Health checks and throttling limits are active.

Immediate Actions

  1. Detect peak load via CloudWatch metric alarms for request rate and latency.
  2. Evaluate whether the load is legitimate or caused by a spike/fault.
  3. If traffic is legitimate, scale application and database resources.

RTO Steps

  1. Increase ECS/EKS task capacity and load balancer target counts.
  2. Scale Aurora reader nodes and DynamoDB on-demand throughput.
  3. Scale MSK broker capacity and partition handling.
  4. Use Route 53 weighted routing to shift excess traffic to Hyderabad if Mumbai is saturated.

Validation

  • Confirm request latency returns to acceptable levels.
  • Verify transaction success rates.
  • Check downstream processing systems for backpressure.

Post-Recovery Activities

  • Analyze peak load event and refine scaling thresholds.
  • Update capacity planning documents.
  • Conduct tabletop exercises for similar traffic patterns.
