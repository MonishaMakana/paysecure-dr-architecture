Runbook 01: Mumbai Region Failure

Scope

This runbook covers failover when AWS Mumbai (ap-south-1) becomes unavailable or impaired.

Objective

  • Restore service using Hyderabad in under 5 minutes
  • Preserve transaction data with RPO < 1 minute
  • Maintain compliance with RBI and data localisation by keeping all data inside India

Preconditions

  • AWS Hyderabad environment is fully provisioned and health-checked
  • Route 53 failover configuration exists with latency-weighted routing
  • Aurora Global Database replica in Hyderabad is available
  • DynamoDB Global Tables are synced
  • Kafka MirrorMaker 2 replication is operating
  • ElastiCache Redis global datastore replica is available

Immediate Actions

  1. Confirm Mumbai region degraded via AWS Health Dashboard and CloudWatch alerts.
  2. Trigger Route 53 failover to Hyderabad using predefined health check status.
  3. Verify API Gateway endpoint is now routing to Hyderabad application endpoints.

RTO Steps

  1. Promote Hyderabad Aurora replica to writer:
  2. Use PromoteReadReplicaDBCluster for Hyderabad Aurora cluster.
  3. Validate writer endpoint health.
  4. Confirm DynamoDB global table writes continue in Hyderabad.
  5. Promote Redis replica:
  6. Use ElastiCache global datastore failover.
  7. Update application Redis endpoint alias if necessary.
  8. Switch Kafka consumers to Hyderabad MSK cluster:
  9. Validate MirrorMaker 2 replication lag.
  10. Update consumer group configuration if automatic failover is not active.
  11. Execute smoke tests for payment flow and reconciliations.

Validation

  • Confirm POST /payment success in Hyderabad.
  • Verify Aurora writer and read endpoints are healthy.
  • Validate DynamoDB table writes and reads.
  • Check consumer lag in MSK and retry on any stuck partitions.
  • Confirm downstream settlement messages continue.

Post-Recovery Activities

  • Document incident and time to recover.
  • Run root cause analysis with AWS Support if needed.
  • Review replication lag metrics and adjust capacity.
  • Schedule a full DR test for the failback process.
