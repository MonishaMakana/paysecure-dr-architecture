Runbook 04: DynamoDB Conflict Resolution

Scope

This runbook covers handling conflicting writes and replication reconciliation for DynamoDB Global Tables.

Objective

  • Resolve inconsistent item versions
  • Ensure idempotent merchant transaction state
  • Maintain RPO < 1 minute and service consistency

Preconditions

  • Global Tables are configured in Mumbai and Hyderabad.
  • Application uses conditional writes for transaction idempotency.
  • Monitoring for ReplicationLatency exists.

Immediate Actions

  1. Identify conflict events using CloudWatch alarms and application error logs.
  2. Pause writes to affected items if needed.
  3. Inspect item versions and LastUpdated timestamps in both regions.

RTO Steps

  1. Reconcile item state by applying last-writer-wins rules.
  2. If necessary, restore the latest valid state from backup.
  3. Re-enable writes once data consistency is verified.

Validation

  • Confirm read-after-write consistency for reconciled items.
  • Validate merchant transaction state with settlement records.
  • Check replication metrics and resolve any outstanding latency.

Post-Recovery Activities

  • Review DynamoDB conflict triggers and adjust schema if needed.
  • Update application logic for stronger idempotency.
  • Document the event and mitigation steps.
